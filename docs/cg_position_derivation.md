# 前轴到质心距离 a_t 推算说明

`sim/configs/default.yaml` 的 `truck_trailer_vehicle` 段当前用 **a_t = 2.21 m**。本文说明这个值怎么算出来的。

## 数据来源

`sim/configs/L4电拖头_首台车_传感器位置参数及车辆参数_20241030-集成答复.xlsx`,Sheet1:

| 行 | 内容 | 值 |
|---|---|---|
| R71 | 名义轴距 L | **4483 mm** |
| R76 | 空载轴荷 | 前桥 **4712 kg** / 中桥+后桥 **4588 kg** |
| R77 | 满载轴荷 | 前桥 5780 kg / 中桥+后桥 18524 kg |

xlsx **没有"a_t"或"质心位置"这种字段** —— 这不是车厂直接出的几何参数,因为 CG 位置取决于货物分布、燃料/电池余量等,实际做法是把车开上称重台,**测每根轴的载荷,反推 CG**。

## 推导

车静止平放在水平地面,前后轴受力平衡(两个未知数 $W_f, W_r$,两个方程:力平衡 + 力矩平衡):

$$W_f = m \cdot g \cdot \frac{b}{L}, \qquad W_r = m \cdot g \cdot \frac{a}{L}, \qquad a + b = L$$

其中 $a$ = 前轴 → CG,$b$ = CG → 名义后轴。

把 $W_r$ 公式反过来解 $a$:

$$\boxed{\;a = L \cdot \frac{W_r}{W_\text{total}}\;}$$

## 代入空载数据

```
a_空载 = 4.483 m × (4588 / 9300)
      = 4.483 × 0.4933
      = 2.211 m
```

写进 yaml:`a_t: 2.21`(保留 3 位有效数字)。

## 交叉验证:用满载数据再算一遍

```
a_满载 = 4.483 m × (18524 / 24304)
      = 4.483 × 0.7622
      = 3.418 m
```

满载 CG 在 3.42 m,空载 CG 在 2.21 m。这个偏移合理 —— 实车装载/挂车时,5th wheel 把重量压到牵引车后桥,CG 自然向后移。

## 物理解释

| 工况 | a (m) | b (m) | 前/后载荷比 | CG 位置直观说明 |
|---|---|---|---|---|
| 空载单机 | **2.21** | 2.27 | 50.7 / 49.3 | 几乎居中,稍微靠前一点 |
| 满载单机 | 3.42 | 1.07 | 23.8 / 76.2 | 显著靠后,在 2 轴附近 |

空载时 CG 大致在车身中间偏前一点,这和"驾驶室 + 电池在底盘前部"的物理直觉吻合。

## 写进 yaml 的值

```yaml
truck_trailer_vehicle:
  L_t: 4.483        # 名义轴距 (m, xlsx R71)
  a_t: 2.21         # 空载 CG 距前轴距离 (m,反推自 R76)
  # b_t 不用直接配,代码里自动 b_t = L_t - a_t = 2.273 m
```

## 注意事项

- **工况一致性**:a_t 必须和 `m_t`、`default_trailer_mass_kg`、`Cf`、`Cr` 处于同一工况。当前都是**单机空载**(m_t=9300、default_trailer=0、Cf/Cr 按 4712/4588 kg 轴荷推算)。如果以后切到带挂或满载,这五个值要一起重算。
- **不要直接拿"轴距 1-2 轴 = 3800 mm" 当 a_t**:那是物理轴的几何位置,不是 CG 位置(以前 yaml 里 `a_t=3.8` 就是这个误读,实际对应"满载 + 带挂、CG 严重后置"那种 15/85 工况,和单机空载不自洽)。
- **粗略验证**:若想交叉验证一台车的 a_t 是否合理,看前后载荷比就行 —— 大多数商用单机空载都在 50/50 ± 10% 区间。
